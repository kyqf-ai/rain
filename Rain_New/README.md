# rain —— 雨量采集托盘程序

常驻后台，通过串口读取雨量计，把每小时/每分钟雨量写入 SQLite（`rain.db`）。
窗口可最小化到右下角托盘；设备掉线、串口故障、电压低时托盘变色并弹出提醒。
设计与取舍见 `docs/DESIGN.md`。程序同时提供一个本地网页界面（默认 <http://127.0.0.1:9099/>），
可直接查看当日 24 小时雨量表、小时柱状图、五项累计指标、按日/月/年查询和报警记录。

> 本包的 Windows 版已经编译好，在 `dist\rain.exe`，可直接复制到目标电脑使用；
> 需要重新编译时见下面第 1 步。第一次上线请按「首次上线检查」逐项确认。

## 1. 得到 rain.exe（三选一）

### A. 本机有或愿意装 MinGW-w64（最直接）
1. 装 MinGW-w64，让 `gcc` 能在命令行运行（MSYS2 或 <https://winlibs.com> 的免安装版都行）。
   目标电脑是 32 位 Windows 就用 32 位 gcc，否则用 64 位。
2. 在本目录运行（需要联网一次，下载 SQLite 源码到 `third_party\`）：
   ```
   powershell -ExecutionPolicy Bypass -File tools\fetch_sqlite.ps1
   build_win.bat test      ← 可选：先在本机跑单元测试
   build_win.bat           ← 生成 dist\rain.exe
   ```
   电脑不能联网：在别的机器从 <https://sqlite.org/download.html> 下载 *amalgamation* 压缩包，
   把里面的 `sqlite3.c`、`sqlite3.h` 拷到 `third_party\` 即可。

### B. 没有编译器：让 GitHub 替你编译
把整个目录推到一个 GitHub 仓库 → 页面上方 **Actions** → 最新一次 *build-windows* → 底部 **Artifacts**，
下载 `rain-win64`（或 `rain-win32`）。工作流会在真实 Windows 上先跑单元测试和启动冒烟测试，再生成 exe。
这是最省事的办法，也顺带给了我们一次"真实 Windows 编译 + 测试"的证据。

## 2. 第一次运行

1. 把 `rain.exe` 放进一个固定文件夹（例如 `D:\RainCollector\`），**数据库、配置、日志都会生成在这个文件夹里**。
2. **先退出原来的 VB 采集程序**——串口同一时刻只能被一个程序占用。
3. 双击 `rain.exe`。第一次会自动生成 `rain.ini`（串口默认 COM1，和原机一致）并显示窗口；
   串口不对就点「编辑配置」改 `port=`，保存后点「重新加载配置」。
4. 窗口里"状态"变成"在线"、托盘图标变绿即成功。

## 3. 日常使用

- **最小化或点 X**：窗口藏到右下角托盘，程序继续采集。**左键点托盘图标**显示窗口。
- **托盘右键菜单**：显示窗口 / 立即同步 / 打开网页 / 打开日志目录 / 开机自动启动（勾选后断电重启也会自动恢复）/ 退出。
- **只有「退出」才会真正停止采集**（会二次确认）。关机、注销时程序会自行干净退出。
- 再双击 `rain.exe` 不会启动第二份，只会把已运行的窗口调出来。
- 图标颜色：🟢 正常　🟡 电池电压低于设备报警值，或设备时钟与电脑相差超过 5 分钟　🔴 故障　⚪ 连接中/已停止。
- 数据在 `rain.db`，可用 DB Browser for SQLite 等工具直接打开：`rain_hour`（每小时一行）、`rain_min`（只存有雨的分钟）、
  `device_state`（最新状态）。`mm = total ÷ unit`，默认 unit=100。

### 网页界面

程序启动时会同时启动一个本地网页服务（默认 <http://127.0.0.1:9099/>）。托盘右键「打开网页」可直接用默认浏览器打开，
也可以在其他电脑上访问：把 `rain.ini` 的 `[web] bind=127.0.0.1` 改成 `0.0.0.0`，再用 `http://这台电脑的IP:9099/`。
网页**没有登录和密码**，只在可信的内网使用；不需要网页时把 `[web] enable=0`。

网页上与原软件对应的内容：

- 顶部时钟、日期，以及五项指标：滑动小时雨量（最近 60 分钟）、全天日降雨量、本次连续雨量（向前累计到最近连续 6 小时无雨为止）、本月降雨量、今年降雨量。
- 当日 24 小时雨量表（整点时段、雨量、累计、状态、气温）、小时柱状图，点柱子可看该小时的分钟明细。
- 前一天/后一天/日期选择；「日报表 / 月报表 / 年报表」直接跳到对应区间的统计。
- 查询统计：按日/按月/按小时区间汇总，显示累计雨量、有雨日数、最大小时/最大日雨量、数据完整度，并可导出 CSV。
- 报警查询：由采集程序保存的电压/时钟状态历史推断（时差超过 5 分钟、电池电压低于设备报警值）；设备状态页显示机号、电压、时钟偏差等。
- 网页每 30 秒自动刷新一次。

网页文件在 `web/index.html`，修改后运行 `python tools\gen_page.py` 重新生成 `src/web_page.c`，再编译。

## 4. 首次上线检查（重要，约 10 分钟）

设备的"有雨"数据帧（AA05）我们没在真机上见过，字节序和单位是**推断**的。请这样核对（在 `cmd` 里，目录为 exe 所在目录；
输出可以重定向到文件发给我）：

```
rain.exe probe "2026-11-05 20" > probe.txt
type probe.txt
```

1. 数据库里已知 2026-11-05 20:00 这一小时的第 2 分钟有 `000A`（0.10 mm）。输出里 **little-endian** 与 **big-endian**
   两段解码，应当只有一段标着 `plausible`，且 `minute 02: 10`、合计 10 计数（0.10 mm）；
2. 一致就保持 `endian=auto`；不一致把 `probe.txt` 发给我，**不要继续入库**；
3. 日志里（`logs\`）会有 `first rain frame #1…` 三行，是前三个有雨小时的原始字节，同样可以发给我核对；
4. 当前小时是否返回实时数据：在整点后 10～20 分钟运行 `rain.exe probe "今天日期 当前小时"`——
   返回数据且 `temp invalid` 说明设备提供实时数据（窗口里"本小时"会实时变化）；
   只返回 `end marker only` 则当前小时在整点后才出现，程序同样正常。
5. 建议新旧程序**错开时间**各跑一段，对比同一小时雨量一致后再正式切换。

其他诊断命令：`rain.exe once`（连一次、同步一轮就退出）、`rain.exe collect`（不带窗口，控制台采集）。

## 5. 配置（rain.ini）

样例见 `rain.ini.sample`，每项都有注释。常用：`[serial] port=`、`[device] machine=`（填了就只接受这个机号）、
`[collect] poll_sec=`（默认 60 秒）、`backfill_hours=`（最多往回补多少小时，默认 72）、
`[web] enable=`（默认 1）、`bind=`（默认 127.0.0.1）、`port=`（默认 9099）。
文件请保存为 UTF-8（记事本"另存为"选 UTF-8）或纯 ASCII。

启动（以及每次"重新加载配置"）后，第一轮会把 `backfill_hours` 窗口扫一遍：库里已有 `final` 的小时直接跳过，
缺失或只存了 provisional 的小时逐个补；设备明确回复"无数据"的空洞记在内存里，当轮不再问；
某个小时连续 3 轮无应答也会被跳过，不会卡住后续读取。补历史期间状态显示"正在补齐历史数据"。
站点名称保存在数据库 `device.name` 里，用任意 SQLite 工具改完后"重新加载配置"即可在界面显示；
`rain.ini` 的 `name=` 只在新设备第一次登记时写入。

## 6. 故障排查

| 现象 | 处理 |
|---|---|
| 红色"串口异常" | COM 口号不对，或被别的程序占用（先退出原 VB 程序）；设备管理器里确认串口号 |
| 红色"设备无应答"/"设备无响应" | 线缆、波特率（9600）；`rain.ini` 里 `trace=1` 重新加载，日志会记录每个收发字节 |
| 红色"机号不符" | `machine=` 与设备实际机号不一致，**不会入库**；清空它或改对 |
| 红色"采集线程无响应" | 程序内部卡住（正常不应出现），请退出重开，并把 `logs\` 发给我 |
| 双击没反应 | 可能已在托盘里运行；点托盘图标，或看任务管理器里有没有 `rain.exe` |
| 开机没有自动运行 | 托盘右键确认"开机自动启动"已勾选；该设置只对当前 Windows 用户有效 |
| 某小时一直缺数据 | 设备已不保存该小时；日志里有 `device has no data for …`，连续 3 轮无应答的小时会被跳过 |
| 无雨也显示 0.1 mm | 1 个计数 = 0.01 mm，10 个计数 = 0.1 mm，正好是翻斗一格。用 `rain.exe probe "…"` 对照旧程序同一小时，确认是设备抖动/测试翻斗还是解析差异 |
